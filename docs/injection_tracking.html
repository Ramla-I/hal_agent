The kinds of constraint

What the grammar can express. Only state_gate has a code generator today — the rest are extracted and recorded, and show up under where the rest went as kind_not_emitted.

kindwhat it means
state_gateYou may only touch this register while some other bit is in the right state — “only write CR1 while the STOP bit is clear”. The workhorse kind, and the only one with a code generator today.
sequenceSeveral steps that must happen in a fixed order — write 0xCA to the key register, then 0x53. Doing them out of order does not work.
write_onceA lock bit you may set only once after reset. A second write is silently ignored by the hardware, so it has to be caught.
clock_gateThe peripheral’s clock must be switched on before any of its registers respond. Applies to the whole peripheral, not one register.
delayYou must wait — some clock cycles or microseconds — after one access before the next one is valid.
read_effectReading the register changes something: it clears a flag, or pops a byte. Not a rule to enforce, but it tells us a check-by-reading would disturb the very state it is checking.
value_relationTwo fields must agree with each other or with the outside world — “CR2.FREQ must equal the APB1 clock frequency”. Documented, not enforceable.
otherA genuine access rule that fits none of the shapes above. Recorded so it is not lost, never turned into a gate.

Where the rest went

Every constraint that did not become a gate, with the stage that dropped it and the grammar kinds involved. The stages, in the order a constraint would meet them:

stage what it iswhat lands here
rejected_at_collectionstage-0 lintNames a register or field that cannot be resolved in the SVD, fails grammar-v2 validation outright, or carries a placeholder name.
kind_not_emittedemitter coverageThe grammar kind has no code generator yet — sequence, delay, write_once, read_effect, value_relation, other. The single largest enforcement gap.
gated_out_by_validatorclosed-book judgeThe validator read the quote without the datasheet in front of it and called the constraint doc_only (genuine but not witness-enforceable) or drop (not a constraint at all).
peripheral_not_in_devicedevice projectionThe manual covers a chip family; this peripheral is genuinely not on the chip injected. Instances that merely share another instance's register-block module are resolved, not dropped.
emitter_rejectedemitterNothing enforceable left after kind filtering, a field name that is not an SVD identifier, a self-defeating same-register read gate, or OR-values the emitter cannot express as one check.
instance_conflict_droppedinstance conflictPeripheral instances share one Rust type and disagreed on the gate for it — two readings of one datasheet sentence with no way to tell which is right, so no gate is emitted at all.
pruned_for_devicegenerated-PAC realityNot expressible against the generated code: the register's access mode has no such operation, or the precondition's field reader is the wrong shape (a 1-bit BitReader has no bits(); a multi-bit FieldReader has no bit_is_set()).
target_unverified_by_locationquote anchoringThe supporting quote never names the register and could not be anchored to the target's own section of the manual, so the evidence cannot be tied to what it claims to constrain.
