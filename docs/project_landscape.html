Where our datasheet rules would bite: a scan of higher-level projects

20 open-source embedded projects read against constraints extracted from their chips' reference manuals. This is a static survey — each project's own Rust source is parsed for hardware register accesses and cross-referenced. Nothing is compiled.

A hit is a candidate, not a bug. unchecked means no precondition field is referenced before the access; corroborated means the project already performs the datasheet-prescribed check nearby. Guards factored into a same-file helper are followed one level, both the wrap-in-a-closure idiom and a plain call beforehand; deeper chains still read as unchecked.

What this cannot see

A static scan sees no runtime guards, so unchecked means candidate, not bug; compile confirmation is the eventual arbiter. Peripheral attribution is heuristic — it comes from the receiver expression, falling back to the module the code lives in. Chip attribution is per path prefix and derived from each driver crate's own build features, not the family in its name; getting that wrong is not conservative, and an earlier run matched Hubris's shared I²C driver against an F4 manual whose I²C is a different peripheral generation, manufacturing 14 findings. Whole-register gates over-approximate: when a rule lists no restricted fields it gates the whole register, though the datasheet note usually attaches to specific bits — read the fields written column before the verdict.

Register writes that leave the typed API entirely

Every compile-confirmed number on this page is a lower bound, and this measures the gap. Enforcement is a trait bound on the register type’s access methods; bit banding writes a register through a raw pointer (bb::set(rcc.bdcr(), 0) — ARM maps each peripheral bit to its own word address), so the write never calls a gated method and compiles whatever markers the register carries. experiments/bitband_scan.py finds these calls, resolves the bit number to a field through the PAC’s own generated accessors, and cross-references the constraints. Across 14 (driver, manual) pairings — every locally available sweep consumer that uses bit banding — it finds 16 writes to constrained fields that no gate can see. “Zero hits” on this page means “nothing went through the gated API”, not “nothing touched the register”.
