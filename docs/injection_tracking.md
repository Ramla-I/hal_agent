# Injection tracking table

## Regenerating this table

```sh
# extraction/enforcement columns — fast, no cargo needed
python applications/pac_codegen/experiments/stm_sweep.py --dry-run
python applications/pac_codegen/experiments/tracking_table.py

# the compile columns additionally need cargo (~1h) ...
python applications/pac_codegen/experiments/stm_sweep.py
# ... and the blocked-HAL notes need
python applications/pac_codegen/experiments/hal_gap.py
```

PAC crates must be provisioned first (`get_pac.py --crate <c> --version 0.16.0`), and the pipeline outputs are read from the
sibling `hal_agent-phase-1d` worktree (`DATA` in `stm_sweep.py`).

Generated by `applications/pac_codegen/experiments/tracking_table.py`
— every number is read from a pipeline artifact, so re-running the
script after new manuals land refreshes the table. One row per
(reference manual, chip, HAL crate).

**PAC** = the generated register-access crate for a chip family
(e.g. `stm32f3`); constraints are injected here. **HAL** = a
higher-level driver crate built on it (e.g. `stm32-hal2`); these are
compiled UNMODIFIED against the injected PAC.

**Each column is a different stage — and they have different
denominators.** The pipeline is:

```
generator  ->  collection lint  ->  judge  ->  emitter + device prune
```

- `constraints found` / `found by kind` = **RAW generator output**,
  before any validation, lint, or de-duplication.
- `validator says enforce` = confirmed by the closed-book judge AND
  witness-enforceable. Its denominator is what survived the stage-0
  collection lint (SVD-resolvable name, valid grammar v2, no
  placeholder, de-duplicated) — NOT the raw count, which is always
  larger. The shortfall is itemised under `where the rest went`.
- `of which via instance alias` — svd2rust gives every peripheral
  INSTANCE a type alias over one shared register-block module
  (`pub type I2C2 = crate::Periph<i2c1::RegisterBlock, ...>`), so
  `i2c2.rs` does not exist and I2C2's registers ARE `i2c1`'s types.
  Constraints extracted for a non-first instance are resolved through
  that map instead of being discarded. Because instances share the
  type, such a gate necessarily covers EVERY instance of the block.
- `enforced` = what actually became **compile-time gates**,
  after the emitter (only `state_gate` has an emitter today) and the
  device-level prune. Every other kind is accounted for under
  `where the rest went`, with the stage that dropped it.

## The kinds of constraint

What the grammar can express. Only `state_gate` has a code
generator today; the rest are extracted and recorded, and appear
under *where the rest went* as `kind_not_emitted`.

- **`state_gate`** — You may only touch this register while some other bit is in the right state — “only write CR1 while the STOP bit is clear”. The workhorse kind, and the only one with a code generator today.
- **`sequence`** — Several steps that must happen in a fixed order — write 0xCA to the key register, then 0x53. Doing them out of order does not work.
- **`write_once`** — A lock bit you may set only once after reset. A second write is silently ignored by the hardware, so it has to be caught.
- **`clock_gate`** — The peripheral’s clock must be switched on before any of its registers respond. Applies to the whole peripheral, not one register.
- **`delay`** — You must wait — some clock cycles or microseconds — after one access before the next one is valid.
- **`read_effect`** — Reading the register changes something: it clears a flag, or pops a byte. Not a rule to enforce, but it tells us a check-by-reading would disturb the very state it is checking.
- **`value_relation`** — Two fields must agree with each other or with the outside world — “CR2.FREQ must equal the APB1 clock frequency”. Documented, not enforceable.
- **`other`** — A genuine access rule that fits none of the shapes above. Recorded so it is not lost, never turned into a gate.

**Fate glossary**, in the order a constraint meets the stages:

1. `rejected_at_collection` (stage-0 lint) — Names a register or field that cannot be resolved in the SVD, fails grammar-v2 validation outright, or carries a placeholder name.
2. `kind_not_emitted` (emitter coverage) — The grammar kind has no code generator yet — sequence, delay, write_once, read_effect, value_relation, other. The single largest enforcement gap.
3. `gated_out_by_validator` (closed-book judge) — The validator read the quote without the datasheet in front of it and called the constraint doc_only (genuine but not witness-enforceable) or drop (not a constraint at all).
4. `peripheral_not_in_device` (device projection) — The manual covers a chip family; this peripheral is genuinely not on the chip injected. Instances that merely share another instance's register-block module are resolved, not dropped.
5. `field_gating_disabled` (switched-off feature) — Every constraint on the register applies to a named FIELD rather than the whole register, and field-level gating is off by default — gating the whole register would demand the precondition for writes to unrelated fields. The emitter builds these fine with --field-level-gating; this is a policy default, not a codegen gap.
6. `emitter_rejected` (emitter cannot express it) — A shape the emitter genuinely cannot translate: a field name that is not an SVD identifier (empty, a bit range, a wildcard), OR-values it cannot express as one check, a self-defeating same-register read gate, or a cross-register source it cannot resolve to a module.
7. `instance_conflict_dropped` (instance conflict) — Peripheral instances share one Rust type and disagreed on the gate for it — two readings of one datasheet sentence with no way to tell which is right, so no gate is emitted at all.
8. `pruned_for_device` (generated-PAC reality) — Not expressible against the generated code: the register's access mode has no such operation, or the precondition's field reader is the wrong shape (a 1-bit BitReader has no bits(); a multi-bit FieldReader has no bit_is_set()).
9. `target_unverified_by_location` (quote anchoring) — The supporting quote never names the register and could not be anchored to the target's own section of the manual, so the evidence cannot be tied to what it claims to constrain.
