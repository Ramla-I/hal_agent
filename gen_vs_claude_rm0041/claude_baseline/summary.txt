**How it was done**

- No PDF tools were available offline, so I wrote a small PDF text extractor in Python (ToUnicode maps plus real glyph widths) and dumped the manual to per-chapter text files.
- Register structure (offset, reset value, size, fields) was generated from the SVD, then twelve parallel sub-agents read their chapters, extracted constraints, and wrote them into the files through a validating helper script.
- Every file was re-validated at the end: JSON parses, filename matches the register abbreviation, fields are in range with no overlaps, and every constraint conforms to the grammar. Zero problems.

**Structure corrections made against the manual**

- BKP register offsets shifted by 4 to match the manual's base address.
- FSMC BCR1 reset 0x000030DB, BCR2–4 0x000030D2, BTR1–4 0x0FFFFFFF; CPSIZE and WRAPMOD fields added.
- TIMx_ARR reset 0x0000FFFF for TIM1, TIM2–5, TIM6/7, TIM12–14 per their register descriptions. TIM15–17 kept 0x0000 as their descriptions state.
- UART4/5 SR reset 0x000000C0; OVER8 and ONEBIT fields added to all USART/UART CR1/CR3; OPM added to TIM13/14 CR1.
- Field name fixes: TIM1 IC1PSC/IC2PSC, WWDG_SR EWIF, RCC_APB1RSTR UART4RST/UART5RST.

**Things to be aware of**

- Cortex-M3 core registers (NVIC, SCB, MPU, SysTick) are not described in RM0041, so their constraint arrays are empty by design. FLASH registers other than FLASH_ACR are documented in PM0063, so only RM0041's statements were recorded.
- The 27 quotes not found verbatim are due to extraction artefacts such as subscripts and hyphenation, not invented text.
- USART1–3 SR reset value was kept at 0x000000C0 although the manual header says 0x00C0 0000, since the manual's own bit table shows TC and TXE set.
