The agent finds most registers and fields for the peripherals it already knows, but it misses many whole peripherals (only ~55 % of the SVD list).  
This indicates that the retrieval step is not pulling the PDF sections where those peripherals are described – often because the reference manual uses slightly different names (e.g., “USART1” instead of “uart1”, “TIM1” sections are titled “Timer 1”, GPIO ports appear as “GPIOx” tables, etc.).  

Semantic search is the right approach, but the current settings are tuned for precision rather than recall:

* **Score threshold = 0.1** discards low‑similarity passages that contain the alternate naming.  
* **Re‑ranking = true** re‑orders by similarity and can drop borderline matches that are needed for the missing peripherals.  
* The query‑rewrite flag is already on, which helps, but we also need to be more permissive in accepting matches.

By lowering the similarity threshold and disabling re‑ranking we keep a larger, more diverse set of passages, increasing the chance of capturing the missing peripheral blocks. The other parameters (semantic search, 50 embeddings, keep tables) already work well and do not need to change.
