Compile-time register-access enforcement · NXP

Witness-gating NXP's published Rust PACs

We took register-access constraints extracted from NXP datasheets, injected them as compile-time witness gates into the published svd2rust PAC crates, and built the real downstream HALs and firmware against the gated PACs. The gate fires wherever a driver touches a constrained register without proving the precondition — turning datasheet rules into type errors.

02What made NXP hard

The gating emitter was built for one svd2rust flavour (stm32-rs). NXP's PACs span five versions in two generic.rs dialects and three naming conventions — it injected nothing, or uncompilable code, until it became dialect-aware.

svd2rustgeneric.rs dialectRegisterSpec1-bit field reader
0.19–0.21early — REG::Writer closures, no return, no from_*/atomics, no Reg DebugCTRL_SPECstruct X_R(FieldReader<bool,…>)
0.35–0.37modern — W<REG> closures, -> REG::Ux, from_*CtrlSpectype SeqidleR = BitReader
stm32-rsmodernCRrstype X_R = BitReader

The emitter now detects the dialect, emits the matching witnessed surface, discovers each register's spec name from the PAC rather than deriving it, resolves the flat single-device instance map (impl Deref for I2C1 { Target = i2c0::.. }), and reads all three field-reader forms. A sub-variant even splits the "modern" line: 0.35 lacks REG::Ux::ZERO (uses default()).

04The bug

lpc8xx-hal · I2cMaster::read_all · src/i2c/master.rs:98

I2C DMA-read arms MSTCTL without waiting for the master to be pending

LPC845 rule: write MSTCTL only when STAT.MSTPENDING is set. The DMA-read entry point enables master DMA during the START/address phase, when the master is not pending — while its DMA-write twin correctly waits first. The write to MSTCTL can be dropped/misapplied, silently breaking the DMA read. Reachable on the normal path through the public read_all API.

// write_all — correct
self.start_operation(address, Rw::Write)?;   // MSTSTART issued → MSTPENDING = 0
self.wait_for_state(State::TxReady)?;         // ← waits until MSTPENDING = 1
self.mstctl.modify(|_, w| w.mstdma().enabled());

// read_all — the bug
self.start_operation(address, Rw::Read)?;     // MSTSTART issued → MSTPENDING = 0
self.mstctl.modify(|_, w| w.mstdma().enabled());   // line 98: no wait — MSTPENDING = 0 here

The gate caught it by flagging the one MSTCTL access in the file that skips the pending handshake every other access performs.

05Why the other 80 are friction, not bugs

The firings land exactly where they should — the I2C master/slave command protocol, the PUF key path, the TRNG entropy-config path, the LPTMR/RTC timers — but these drivers are disciplined and uphold each precondition imperatively. The witness API would simply formalize what they already do:

  • lpc55-hal — every MSTCTL write sits beside a while stat.mstpending()… poll; PUF CODEINPUT/KEYOUTPUT guarded by if stat.codeinreq() / keyoutavail(); ADC SWTRIG only after enable.
  • embassy-imxrt — all 44 I2C command writes are pending-gated (busy-wait or explicit if …pending()); all 5 TRNG config writes are bracketed by MCTL[PRGM]=1 — the entropy source is never configured outside programming mode.
  • mk20dx-hal — LPTMR PSR/CMR always written after disabling the timer; RTC IER/TAR rely on the reset-state write-access bits the HAL never clears.
  • bootleby — compiles clean against the gated PAC; it touches none of lpc55's gated registers witness-free.

The field pass confirms the whole-register conclusion with field precision. All 13 distinct field-gates are friction — the drivers establish each field's precondition imperatively:

  • mk20dx-hal (9 FTM gates: SC.PS/CLKS/CPWMS, POL, SWOCTRL, MODE.FTMEN/INIT, DEADTIME, QDCTRL) — the HAL sets MODE.WPDIS=1 at every FTM entry (split/pwm/quad) and never re-enables write-protection; the config methods are reachable only through typestate handles minted after that. Plus CMP CR0.FILTER_CNT (CR1.SE never set) and PDB SC.LDOK (documented enable-first, misuse a benign no-op, test-pinned).
  • lpc55-hal (2 gates) — FLEXCOMM.PSELID.PERSEL (×25 sites) written right after syscon.reset() so LOCK=0, configure-then-lock; RNG.DATA_SEL sits in dead unimplemented!() code with no caller.
  • embassy-imxrt and lpc8xx-hal produce 0 field firings — mimxrt685s's field-gated security/lock registers (PUF KEYLOCK, AHB SECLOCK, DBG_LOCKEN, I3C) are never written by the HAL, and lpc845 has no field-scoped constraints at all.

Field mode's value is diagnostic precision, not additional bugs — its 205-vs-81 volume is exactly why the whole-register hard gate is the better default for a bug-hunt. Across both modes, all 286 injected compiler errors were triaged to one real bug.
