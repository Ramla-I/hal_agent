---bkp---
The BKP peripheral defines backup data registers **BKP_DRx** for x = 1 … 20, two control registers (**BKP_CR**, **BKP_CSR**) and no information for the requested indices beyond 20.  
Using the address‑offset formula provided in the datasheet we calculated the offsets for the registers that exist:

* **BKP_DR1** – offset 0x04  
* **BKP_DR3** – offset 0x0C  
* **BKP_DR18** – offset 0x5C  
* **BKP_DR20** – offset 0x64  

All DR registers share the same reset value (0x00000000), size (16 bits) and a single read‑write field **D[15:0]** (backup data).  
A note in the **BKP_CSR** description states that writes to any BKP_DRx are ignored while the **TEF** flag is set; this is captured as a write‑access constraint for each DR register.

**BKP_CR** (offset 0x30) contains two read‑write bits **TPAL** (bit 1) and **TPE** (bit 0). The datasheet advises that **TPAL** should only be changed when **TPE** is cleared – added as an access constraint.

**BKP_CSR** (offset 0x34) contains five fields with the following access types and constraints:
* **TIF** (bit 9) – read‑only, cleared by writing 1 to **CTI** or by resetting **TPIE**.
* **TEF** (bit 8) – read‑only, cleared by writing 1 to **CTE**.
* **TPIE** (bit 2) – read‑write, may be set only when **TPE** (in **BKP_CR**) is set.
* **CTI** (bit 1) – write‑only, writing 1 clears **TIF**.
* **CTE** (bit 0) – write‑only, writing 1 clears **TEF**.

All other requested registers (indices 22, 25, 26, 28, 32, 37, 38, 42, 36) fall outside the defined range (1‑20); therefore no information is available for them.

---crc---
The datasheet provides explicit information for all three requested CRC registers.  
- **CRC_DR** is at offset 0x00, 32‑bit wide, reset to 0xFFFFFFFF and consists of two read‑write sub‑fields covering bits 31:16 and 15:0.  
- **CRC_IDR** is at offset 0x04, 32‑bit wide, reset to 0x00000000. Bits 31:8 are reserved (must stay at reset value) and bits 7:0 form an 8‑bit read‑write data field.  
- **CRC_CR** is at offset 0x08, 32‑bit wide, reset to 0x00000000. Bits 31:1 are reserved (must stay at reset value). Bit 0 is the **RESET** bit, which is write‑only, self‑clearing by hardware.  

The only access constraints mentioned are:
1. Reserved bits (31:1 in CRC_CR and 31:8 in CRC_IDR) must remain at their reset values when writing.  
2. The **RESET** bit can only be written as ‘1’; it is automatically cleared by hardware after the reset operation.

No address calculations are required because the offsets are given directly.

- **FSMC_BCR1** and **FSMC_BCR3** are the chip‑select control registers. Their address offsets follow the formula `0xA000 0000 + 8 × (x‑1)`; using the supplied `calculate_address_offset` calls we obtain offsets `0x0` for BCR1 (x = 1) and `0x10` for BCR3 (x = 3). - **FSMC_BWTR1** is the write‑timing register. Its offset follows `0xA000 0000 + 0x104 + 8 × (x‑1)`; the function call yields `0x104` for x = 1. The reset value is `0x0FFFFFFF`. The register is only effective when the corresponding BCR’s **EXTMOD** bit is set, which the datasheet explicitly states; this forms an access‑constraint for write operations to FSMC_BWTR1.  

All subfields are listed explicitly, and no other access constraints are described in the provided excerpts.

These constraints are captured in the `access_constraints` section.
